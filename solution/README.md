# 居灵 TakeHome 工程题：矩形物品自动装箱 / 平面布局（纯 Java，零第三方依赖）

把冰箱、货架、离地架、制冰机等矩形设备自动摆进多边形（含凹形、斜墙）房间，
满足不穿墙、不重叠（可共边）、与墙平行/垂直、优先贴墙、避让门洞与内开门
摆动区、冰箱正面留 800mm 开门空间，并**保证“人进门后能走到房间各处”**，
最后输出每个物品的 `center[x,y]`、`angleDeg` 和 SVG 平面图。

单位：毫米。

## 一、编译与运行（Windows PowerShell）

```powershell
cd solution
# 编译（UTF-8，零依赖，只需 JDK）
javac -encoding UTF-8 -d out src\com\juling\packing\*.java
# 运行：参数是 example*.json 所在目录（这里是上一级素材目录）
java -cp out com.juling.packing.Main ".."
```

运行后在该目录的 `result\` 下生成（每个例子一组）：

| 文件 | 含义 |
|---|---|
| `placement_exampleN.json` | 结果：`feasible` 与每件物品 `center`、`angleDeg`、尺寸、类型 |
| `exampleN.svg` | 平面布置图（墙体、门、门摆动区、冰箱开门区、各设备） |
| `exampleN_reach.svg` / `.png` | 通行可达性图：绿色=人能走到，红色=被摆死的通道，黄=门摆动区，蓝虚线=冰箱开门区 |

`angleDeg` 约定：`0°` 时物品 length 边沿 +x 方向，`90°` 时沿 +y 方向。

## 二、工程结构（src/com/juling/packing/）

| 类 | 职责 |
|---|---|
| `Vec` | 二维向量：加减、点积、叉积、旋转、归一化、点到线段距离等 |
| `Obb` | 有向包围盒（中心点 c、轴向 u/v、半长 hl/半宽 hw）；SAT 相交判定、角点/边、采样点 |
| `Geometry` | 点在多边形内、矩形是否整体在多边形内（网格采样）、墙体内法向、共线重叠、bbox 等 |
| `Room` | 解析房间多边形、门；构造内开门 N×N / 外开门 600 深的门摆动禁区 `blockedZones`；`fits()` 判定 |
| `Item` / `Placement` | 设备定义（类型、长宽）；一次摆放（中心、角度、冰箱开门区） |
| `PackingSolver` | 布局求解器（核心算法，见下） |
| `Reachability` | 通行可达性检查（栅格 + flood fill），并独立输出 reach 图 |
| `SvgWriter` | 平面布置 SVG 输出 |
| `Json` | 极简手写 JSON 解析/序列化（无第三方库） |
| `Main` | 遍历 4 个例子：读入→求解→写 JSON/SVG/可达性图 |

## 三、算法怎么做的

### 1. 几何层：全部用“有向矩形 OBB”，不用轴对齐包围盒
- 斜墙房间里物品是斜的，轴对齐框会误判；`Obb` 用两条正交轴表示任意角度矩形。
- 两矩形是否碰撞用 **SAT（分离轴定理）**，共边（距离 0）判为合法。
- “物品是否在房间内”用矩形内部网格采样 + 点在多边形内判定（`rectInsidePolygon`）。
- 物品角度只取墙向或墙向 ±90°，保证与墙平行/垂直。

### 2. 门与摆动区
- 内开门：在门内侧建 N×N（N=门宽）矩形禁区；外开门：建 600mm 深通行矩形。
- 禁区在 `Room.blockedZones` 中，任何物品本体都不得与之相交（`Room.fits()` 已检查）。

### 3. 冰箱开门区
- 冰箱背面依托墙时，在其正面外扩一个 1220×800 的开门净空矩形；
- 该净空必须落在室内、不能压门摆动区、不能压其他物品，否则该摆法废弃；
- 它是“开门瞬间”的临时净空，**不作为永久障碍**参与通行判定（关门后即普通地面）。

### 4. 大件先放、条带成组（PackingSolver，两阶段 + 回溯）
- **阶段一：大件（冰箱、制冰机）先放。** 候选来自“沿墙滑动 + 墙角/门角/已放物品角点对齐”，
  两种朝向都枚举。评分 = 贴墙长度 + 两邻边贴墙（占角）+ **条带可装箱件数** − 距基准角距离；
  只要会导致任何一个条带放不下就重罚，迫使大件占端部/角部、把连续长墙让给货架。
- **阶段二：条带（货架、离地架）按类型成组、沿墙成列。**
  同一类型优先在同一面墙的一段连续区间里**首尾相接、整组一次排下**
  （货架集中到最长的连续墙、短条填其余墙），并优先更长的主墙；
  条带只允许“长边贴墙、进深 400、正面朝通道”，禁止“端面贴墙、进深=长度”的横档摆法
  （那种摆法排与排之间无法取货）。
- 每放一件都立刻做通行可达性校验；大件摆法回溯，阶段二失败再退回逐件候选的贪心回溯兜底。

### 5. 通行可达性
- 在房间包围盒上铺 150mm 栅格；把门摆动区和每件物品各外扩 175mm
  （对应约 350mm 的最小通行净宽），得到“中心线可通行格”。
- 从门内侧周边撒入口种子，做四邻域 **flood fill（灌水）**。
- **以空房间（只有门区）的可达结果为基准**：墙体与门区自身围成的窄缝
  （例如斜墙与门端交汇处，人本来就无法利用的建筑死角）在空房间里就走不到，不追责；
  只有“空房间走得到、摆上设备后走不到”的格子才算被围死，判该摆法非法。
  这样既能抓住“冰箱/货架堵住连通口、把门围起来”，又不会被建筑自身窄缝误报。

## 四、四个例子的结果

四个例子均 `feasible=true`，且可达性图中**没有任何红色死角**：

- example1（斜墙、外开 N=1000、含制冰机，8 件）：3 货架沿长斜墙成列，2 离地架沿顶斜墙，
  冰箱沉底，制冰机让开门区。
- example2（外开 N=700，8 件）：冰箱占角，货架沿顶/右墙成排，离地架沿左墙。
- example3（L 形、内开 N=700，9 件）：冰箱在图纸位，**5 货架沿左墙成列、正面让出 800mm 主通道**，
  2 离地架沿南墙、1 个在东墙南端补角；进门后沿主通道可一路走到底。
- example4（外开 N=900，6 件）：冰箱占左上角、正面留 800，离地架沉底，货架补右侧。

 的压门观感来自旧布局堵连通口，
   已由通行可达性约束 + 成组布局彻底解决。
