# 居灵 TakeHome 工程题 — README

## 一、AI 使用说明 & 核心代码实现逻辑

### 1.1 AI 工具使用说明

- **使用的 AI 工具**：Claude、Doubao
- **AI 主要帮助的部分**：

  - **思路拆解**：把题目约束拆成"几何 / 门区 / 大件 / 条带 / 可达性"五个独立可测试的子模块。
  - **代码生成**：几何原语（OBB、SAT 碰撞、点在多边形内）、SVG 输出、手写 JSON 解析器等样板代码。
  - **Debug**：可达性误报（建筑自身窄缝被当成"摆死"的通道）定位与修复。
- **我自己理解并调整的关键逻辑**：
  - **可达性基准对比法**：AI 最初方案会把空房间里的几何死角也算成"被堵死"。我理解了 flood-fill 的逻辑后，调整为"先跑一次空房间、再跑一次摆了设备的房间，只对差集追责"，避免斜墙 + 门端汇合处的窄缝被误报。
  - **条带成组约束**：AI 一开始只按单件贪心贴墙，出现"货架端面贴墙、进深=长度"的横档摆法。我根据实际使用场景加了"长边贴墙、同类型同墙成列、首尾相接"的硬约束，保证通道方向可取货。
  - **大件惩罚项**：在评分里加了"若该摆法让任何一条连续墙条带放不下剩余货架则重罚"，迫使冰箱/制冰机让出长墙给货架——这条规则是基于对 4 个算例的观察自己加上去的。
  - **实际使用情况**：AI根据算法和调整后的规则也会按照设置好的规则去摆放相应的物品，针对过道、开门、实际拐角等不能够理解到是否符合实际使用，所以AI写完之后还需要调整细节。

### 1.2 核心代码实现逻辑（详见 `solution/README.md`）

整体是一个 **两阶段 + 回溯** 的布局求解器，纯 Java、零第三方依赖。

1. **几何层（OBB + SAT）**
   - 所有矩形用"中心 + 两条正交轴 + 半长/半宽"表示，支持任意角度（斜墙房间）。
   - 碰撞用 SAT 分离轴定理，共边（距离 0）合法。
   - "矩形是否在房间内"用内部网格采样 + 点在多边形内判定。

2. **门与摆动区（Room）**
   - 内开门：在门内侧建 N×N（N=门宽）禁区。
   - 外开门：建 600mm 深通行矩形。
   - 任何物品本体不得与禁区相交。

3. **冰箱开门区**
   - 冰箱依托墙时，正面外扩 1220×800 净空矩形；该净空需落在室内、不压门区、不压其它物品；
   - 它是临时净空，**不参与**通行判定。

4. **求解器（PackingSolver）**
   - **阶段一**：大件（冰箱、制冰机）先放——沿墙滑动 + 墙角/门角/已放物品角点对齐，两种朝向都枚举；评分 = 贴墙长度 + 占角 + 条带可装箱数 − 距基准角距离。
   - **阶段二**：条带（货架、离地架）按类型成组、沿墙成列——同类型优先在同一面连续墙区间首尾相接；禁止横档摆法。
   - 每放一件立刻校验通行可达性；阶段二失败会回溯到阶段一。

5. **通行可达性（Reachability）**
   - 150mm 栅格 + 物品/门区外扩 175mm（≈350mm 最小通行净宽）；
   - 从门内侧撒种子做四邻域 flood fill；
   - 以空房间可达结果为基准，只对"空房间走得到、摆上后走不到"的格子追责。

## 二、运行环境及运行方式

- **语言**：纯 Java（JDK 8+ 即可）。
- **操作系统**：Windows（示例命令为 PowerShell；Linux/macOS 把分隔符换成 `/` 即可）。
- **入口类**：`com.juling.packing.Main`
- **源码位置**：`solution/src/com/juling/packing/*.java`

### 运行步骤（Windows PowerShell）

- **直接运行**：可以直接在IDEA中运行`solution/src/com/juling/packing/Main.java`代码也可以。

```powershell
cd solution
# 编译
javac -encoding UTF-8 -d out src\com\juling\packing\*.java
# 运行：参数是 example*.json 所在目录（本项目的根目录）
java -cp out com.juling.packing.Main ".."
```

运行后会在项目根目录的 `result\` 下生成每个例子的：

- `placement_exampleN.json` — `feasible` 与每件物品的 `center / angleDeg / 尺寸 / 类型`
- `exampleN.svg` — 平面布置图（墙体、门、门摆动区、冰箱开门区、各设备）
- `exampleN_reach.svg` / `.png` — 可达性图（绿=能走到，红=被堵死，黄=门摆动区，蓝虚线=冰箱开门区）

## 三、既定输入的输出示例

### example1 — 斜墙房间，外开门（N=1000），含制冰机，共 8 件

**输入要点**
- boundary：7 个顶点（含一段斜墙）
- door：`[[7121.7, 32746.5], [7121.7, 31746.5]]`，`isOpenInward=false`
- 物品：`fridge(1220×1330)`、`iceMaker(760×850)`、`shelf-1/2/3(1000×400)`、`overShelf-1/2/3(600×400)`

**输出（节选自 `result/placement_example1.json`）**

```json
{
  "feasible": true,
  "doorWidth": 1000,
  "doorOpenInward": false,
  "placements": [
    { "item": "iceMaker",   "center": [6141.74, 31321.49], "angleDeg": 0    },
    { "item": "fridge",     "center": [6405.85, 29407.38], "angleDeg": 0    },
    { "item": "shelf-1",    "center": [4761.70, 31945.04], "angleDeg": 105.85 },
    { "item": "shelf-2",    "center": [5698.30, 32211.38], "angleDeg": 105.85 },
    { "item": "shelf-3",    "center": [6635.00, 32477.60], "angleDeg": 105.85 },
    { "item": "overShelf-1","center": [5127.90, 29297.50], "angleDeg": 0    },

    { "item": "overShelf-3","center": [6505.85, 30167.38], "angleDeg": 0    }
```

布局解读：3 个货架沿斜长墙成列（约 105.85°），3 个离地架沿顶墙排开，冰箱沉底角、制冰机让开门区。可达性图中**无红色死角**。

### example2 — 外开门（N=700），8 件

- `feasible: true`
- 冰箱占右下角，2 货架沿顶墙、1 货架沿右墙，3 离地架沿左墙。

### example3 — L 形房间，内开门（N=700），9 件

- `feasible: true`
- 5 货架沿左墙成列，正面让出 800mm 主通道；2 离地架沿南墙、1 个在东墙南端补角；进门后沿主通道一路走到底。

### example4 — 外开门（N=900），6 件

- `feasible: true`
- 冰箱占左上角、正面留 800；离地架沉底；货架补右侧。

四个例子均可行（`feasible=true`），且可达性图中没有任何被摆死的通道。详细 SVG 与可达性图见 `result/` 与 `solution/preview/`。
